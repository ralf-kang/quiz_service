# 정보처리기사 기출 스타일

발행: 한국산업인력공단(HRD-Korea). 필기 5과목(소프트웨어 설계 / 소프트웨어 개발 / 데이터베이스 / 프로그래밍 / 정보시스템 구축관리), 실기 별도. 본 팩은 필기 객관식 기준.

## 시나리오 기반 출제 원칙 (최우선)

기출은 단순 개념 암기가 아닌, **가상 프로젝트·요구사항 시나리오를 제시하고 그 안의 설계 오류·누락 요건·부적합 선택을 식별하는 형태** 입니다.
강의노트의 용어 정의를 그대로 묻지 말고, **가상 프로젝트(예: 학사관리 재구축, 모바일 결제 모듈)·가상 요구사항(예: "동시접속 1만명, 응답 2초 이내")·가상 코드 스니펫** 을 등장시켜
그 안에서 위반된 원칙·잘못된 패턴·누락된 단계를 식별하도록 stem 을 구성합니다.

- 예시 1: "P사의 사내 인사시스템 재구축 프로젝트에서 다음과 같은 요구가 있었다. ① 모듈 결합도 최소화 ② 변경 영향 범위 최소화. 아래 4개 클래스 다이어그램 중 위 요구를 가장 잘 만족하는 것은?"
- 예시 2: "다음 SQL 은 신규 회원가입 트랜잭션이다. (코드 80자) 동시 접속자 폭주 시 발생할 수 있는 이상 현상과 가장 직접적 해결책은?"

## 형식
- 5지선다 객관식이 절대 다수. 단답·단순계산은 4지선다 비율도 있으나 모두 5지로 통일.
- stem 평균 50~120자. 가끔 코드 발췌(파이썬/자바/C/SQL/UML) 가 stem 또는 보기에 등장.
- 보기들은 길이가 거의 같은 명사구·짧은 절. 코드 발췌일 때는 한 줄 단위.

## 어투
- "...에 대한 설명으로 옳은 것은?"
- "...의 특징으로 가장 거리가 먼 것은?"
- "다음 SQL 의 실행 결과로 옳은 것은?"
- "다음 중 RAID-5 의 특징으로 옳지 않은 것은?"

## 지문 블록 가이드
- 단답형 위주이므로 passage 사용은 5문항 중 1개 이하. 사용 시 코드/UML/요구사항 명세 발췌(150~300자) + 후속 문항 1~2.

## 빈출 영역 어휘
- 디자인 패턴(GoF), 정규화/이상현상, 트랜잭션 ACID, OSI 7계층, 라우팅 알고리즘,
  소프트웨어 생명주기 모형, 형상관리(Git), 보안(인증·인가·해시), 빅오 표기.

## 예시 stem (스타일 참고용)
- "GoF 디자인 패턴 중 객체의 생성 책임을 분리하여 다양한 형태의 객체를 만들 때 사용하는 패턴은?"
- "관계형 데이터베이스의 정규화 과정에서 이행적 함수 종속을 제거하는 단계는?"
